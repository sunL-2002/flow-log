## 二、核心用户场景细化
### 场景1：日常专注追踪（高频）
触发时机 ：工作日开始，用户打开电脑

用户目标 ：无感知记录一天的工作内容

当前流程 ：

```
用户打开IDE → 开始编码 → 被钉钉消息打断 → 回复消息 
→ 继续编码 → 开会 → 回来继续编码 → 下班
```
FlowLog介入后 ：

```
后台自动识别：
┌──────────────────────────────────────────────┐
│ 09:00-09:15  启动阶段                        │
│   └─ VS Code 打开，无输入 → 项目准备         │
│ 09:15-11:30  深度编码                        │
│   └─ VS Code + 频繁输入 → 开发登录模块       │
│ 11:30-11:45  即时通讯                        │
│   └─ 钉钉窗口活跃 → 回复工作消息              │
│ 11:45-12:30  会议                            │
│   └─ 腾讯会议窗口 → 需求评审会               │
└──────────────────────────────────────────────┘
```
关键设计点 ：

- 零操作启动：开机自启，无需手动开始
- 智能断点识别：输入停顿超过5分钟自动标记"可能中断"
- 非侵入式通知：仅在状态栏显示当前识别结果，不打断工作流
### 场景2：周报生成（周频）
触发时机 ：周五下午或周一早上

用户目标 ：快速生成可用的周报内容

当前痛点 ：

- 需要翻看Git提交记录、聊天记录回忆做了什么
- 写周报耗时30分钟以上
- 容易遗漏重要工作项
FlowLog解决方案 ：

```
┌──────────────────────────────────────────────┐
│ 📊 本周工作概览                              │
│                                              │
│ 总专注时长：28.5小时（较上周+2.3h）          │
│ 编码：18h | 会议：6h | 沟通：4.5h            │
│                                              │
│ 📝 周报草稿（可一键复制）                    │
│ ────────────────────────────────────────     │
│ 1. 完成登录模块开发（周一、周二）            │
│    - 用户认证接口                            │
│    - 密码加密逻辑                            │
│ 2. 参与需求评审会议（周三）                  │
│ 3. 修复线上Bug 3个（周四）                   │
│ 4. 代码评审与文档更新（周五）                │
│                                              │
│ [复制到剪贴板]  [编辑调整]  [导出详细版]     │
└──────────────────────────────────────────────┘
```

### 场景4：手动修正（低频但必要）

### 交互设计原则 1. 认知负荷最小化
```
❌ 错误设计：
┌────────────────────────────────────┐
│ 请选择活动类型：                   │
│ ○ 深度编码                         │
│ ○ 轻度编码                         │
│ ○ 代码审查                         │
│ ○ 技术调研                         │
│ ○ 文档编写                         │
│ ...（10个选项）                    │
└────────────────────────────────────┘

✅ 正确设计：
┌────────────────────────────────────┐
│ 自动识别：编码                     │
│ 不对？[点此修正] → 弹出3个主分类   │
└────────────────────────────────────┘
``` 2. 渐进式披露
```
第一层（默认显示）：
- 今日专注时长
- 当前活动状态

第二层（点击展开）：
- 时间轴概览
- 分类占比

第三层（深入查看）：
- 详细时间轴
- 手动修正
- 数据导出
``` 3. 正向反馈优先
```
❌ 避免负面表达：
"今天摸鱼时间过长，请改进"

✅ 采用正向表达：
"今天专注3小时，比昨天进步了！
 继续保持，明天挑战3.5小时"
```
## 五、潜在风险与隐私考量
### 隐私风险矩阵
风险类型 风险等级 影响范围 缓解措施 窗口标题泄露敏感信息 高 个人隐私 本地存储 + 敏感词过滤 被用于员工监控 高 用户信任 明确产品定位 + 技术限制 数据被第三方获取 中 数据安全 端到端加密 + 无云同步 误识别造成困扰 中 用户体验 置信度标注 + 轻量修正
